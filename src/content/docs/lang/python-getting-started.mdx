    [Python install manager](https://docs.python.org/3/using/windows.html),

  </TabItem>

### Windows: stop opening the Microsoft Store

If typing `python` or `python3` opens the Store, Windows is running an
**App Installer shortcut**, not your interpreter.

1. Open Start and search for **Manage app execution aliases**.
2. Find the **App Installer** entries for `python.exe` and `python3.exe`.
3. Switch both **Off**, then reopen your terminal.

On Windows 11, the same page is under **Settings → Apps → Advanced app settings
→ App execution aliases**. Turn off the App Installer entries specifically;
keep aliases for an installed Python or Python install manager enabled.
[Microsoft documents this Store shortcut and how to disable it](https://learn.microsoft.com/en-us/windows/python/beginners#why-does-running-pythonexe-open-the-microsoft-store).

```powershell
py -3.14 --version
Get-Command python -All
```

The `py` launcher selects an installed interpreter without relying on the
`python` Store shortcut. Disabling a shortcut does **not** install Python or
add it to PATH. If `py` works but `python` is missing, you can keep using `py`
outside a virtual environment, or enable the installer's **Add Python to PATH**
option. Inside the activated `.venv` below, `python` resolves to that environment.

## Install your first tool: pipx

```sh
pipx ensurepath
```

Reopen the terminal, then:

```sh
pipx --version
```

The install steps above included [pipx](https://pipx.pypa.io/latest/how-to/install-pipx.html).
It installs each Python CLI application in its own virtual environment and puts
its commands on PATH, so tools can have different dependencies. It also makes
updates easy later. Shared commands here work in Bash, zsh, and PowerShell
unless a tab says otherwise.

## Play a couple of terminal games

```sh
pipx install terminal-games
```

```sh
terminal-games
```

[Terminal Games](https://github.com/ayu5h-raj/terminal-games) runs on macOS,
Linux, and Windows with Python 3.12+. Use a terminal at least 80×24; Windows
Terminal is a good choice on Windows. Arrows navigate the menu, Enter selects,
and `q` quits.

Start with these two:

| Game | Why play it | Keys |
| --- | --- | --- |
| Snake | A quick arcade break: eat food and keep growing without hitting yourself or a wall. | Arrows or WASD steer; `p` pauses; `q` returns to the menu. |
| Minesweeper | A slower logic puzzle with three difficulty levels. | Arrows or WASD move; Space reveals; `f` flags; `r` restarts; `q` returns to the menu. |

The same collection includes Tetris, 2048, and word games. pipx installs the
application's dependencies automatically; no repository clone is needed.


An activated environment puts its own `python` first on PATH. Check it:

```sh
python -c "import sys; print(sys.executable)"
```

The path should point inside `python-starter/.venv`. Keep your scripts outside
`.venv`, and exclude that directory from Git. Each project gets its own
environment; see [Python's virtual environment guide](https://docs.python.org/3/library/venv.html).

### Hello, world

Create this file in your editor:

```python title="hello.py"
print("Hello, Python!")
```

```sh
python hello.py
```

Prints `Hello, Python!`. Python runs the script through its interpreter;
there is no separate build command.

### A greeting with an argument

Replace `hello.py` with:

```python title="hello.py"
import sys


def main():
    name = sys.argv[1] if len(sys.argv) > 1 else "world"
    print(f"Hello, {name}!")


if __name__ == "__main__":
    main()
```

```sh
python hello.py Bryan
```

Prints `Hello, Bryan!`; without an argument it greets `world`. `sys.argv[0]`
is the script name. The length check avoids accessing a missing argument.
`f"...{name}..."` inserts the variable into a string. Indentation defines blocks;
use four spaces. The `__main__` guard runs `main()` when the file is executed,
while allowing it to be imported without running the greeting.

## Basics worth keeping

Install a library into this project's activated environment:

```sh
python -m pip install rich
```

```sh
python -c "from rich import print; print('[bold cyan]Hello, Python![/bold cyan]')"
```

[Rich](https://github.com/Textualize/rich) adds formatted terminal output.
Use `python -m pip` so package installation targets the same interpreter that
runs your script. For CLI applications, keep using pipx.

Install a formatter and linter as a standalone tool:

```sh
pipx install ruff
```

```sh
ruff format hello.py
ruff check hello.py
```

[Ruff](https://docs.astral.sh/ruff/) formats code and finds common mistakes.
To record this project's installed libraries:

```sh
python -m pip freeze > requirements.txt
```

Commit `requirements.txt`. In a new activated environment, reproduce those
versions with `python -m pip install -r requirements.txt`.

| Command or concept | Remember |
| --- | --- |
| `python` | Open the interactive interpreter; `exit()` leaves it. |
| `python hello.py` | Run a script using the active environment. |
| `python -m pip` | Run pip using that same interpreter. |
| `pipx install` | Install a CLI application with isolated dependencies. |
| `python -m pip check` | Check installed libraries for dependency conflicts. |
| `deactivate` | Leave the virtual environment. Activate it again next time you work on the project. |

If pip reports `externally-managed-environment`, you're probably using the OS
or Homebrew Python outside a virtual environment. Activate `.venv` for project
libraries, or use pipx for applications. Avoid `sudo pip` and
`--break-system-packages`.

## Keep Python and your tools current

<Tabs syncKey="os">
  <TabItem label="macOS">
    ```bash
    brew update
    brew upgrade python pipx
    ```
  </TabItem>
  <TabItem label="Linux">
    ```bash
    sudo apt update
    sudo apt install --only-upgrade -y python3 python3-venv python3-pip pipx
    ```

    Debian/Ubuntu; use your distribution's package manager on Fedora or Arch.
  </TabItem>
  <TabItem label="Windows">
    ```powershell
    winget upgrade --id Python.Python.3.14 --exact --source winget
    py -3.14 -m pip install --user --upgrade pipx
    ```

    Updates within the installed Python 3.14 release family.
  </TabItem>
</Tabs>

Check the game's environment for available package updates:

```sh
pipx runpip terminal-games list --outdated
```

Update the game collection, or every pipx application:

```sh
pipx upgrade terminal-games
```

```sh
pipx upgrade-all
```

Inside your project environment, use `python -m pip list --outdated` to check
libraries and `python -m pip install --upgrade rich` to update one. Refresh
`requirements.txt` after an intentional update. Python itself, pipx applications,
and project libraries have separate update paths.

After moving to a new Python minor version, recreate project environments with
that interpreter and reinstall their requirements. pipx applications can be
rebuilt with `pipx reinstall-all --python python3` on macOS/Linux, or
`pipx reinstall-all --python (py -3.14 -c "import sys; print(sys.executable)")`
in PowerShell (adjust the selected version for the new interpreter).
